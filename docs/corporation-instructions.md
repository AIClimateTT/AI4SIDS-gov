## Start, or continue a draft

Home has a box that asks what is happening.

- If **Unfiled draft** is showing, press **Resume**. That is the report you started and have not sent.
- To start a new report, type what is happening and send it. You are taken into the conversation.

**Live now** lists events that are still running. **Recent filings** lists reports already sent.

## Describe what happened

Type in ordinary sentences: the alert, where it is, what was damaged, injuries, deaths, and what the corporation has done. You can correct a figure in a later message (“change the sandbags to 20”).

The reply confirms what it captured and may ask one or two short questions. Answer those.

If the reply says **I could not read that update. Please try again in a short sentence**, send that update again in a shorter message. Anything already listed under Facts is still there.

## Check Facts before you send

Open the **Facts** tab. The report is built from this list.

Check these boxes, and type them if they are empty:

- **Situation overview** — the alert and what it caused, in your own words
- **Alert wording** — the alert as you would write it on the report
- **Present activity** — what is happening now

Then check each incident and each situation log. The count at the top of the list is what will be reported. If you described three incidents and the list shows one, the other two were not captured. Send them again, or press **+ Add manually**.

Use **Edit** to correct a row, and **Remove** to drop a row that should not be there.

A box or row you type yourself stays as you left it. A later message will not replace it.

## Confirm the event

A yellow card appears after the first update if the report is not yet tied to an event. It stays until you confirm.

- If the event is already running, press **This is part of** that event.
- Otherwise type the event title, choose the hazard, set the start date, and press **Confirm event**.

You can keep typing while the card is up. A report that includes incidents cannot be issued until the event is confirmed.

## Read the report, then issue it

Open the **Sitrep** tab. **Refresh** and **Issue** wait while the report is being prepared.

The badge reads **Not issued** until you send it.

- **Draft** is the checking copy. It may show short codes beside figures.
- **Final** is the report that will be sent. Read this one. It should match the Facts list, including the overview, the alert wording, and the present activity when those boxes are filled.

If you change anything on Facts after this, the tab tells you the facts have changed. Press **Refresh**, then read **Final** again.

Press **Issue** when Final is right.

**Download PDF** is on the Final view. It opens the print window if you need a copy.

## After you issue

That conversation closes. The report cannot be changed from there. A correction is a new report: go back to Home and start again.

The sent report appears under **Recent filings** on Home.

## A spreadsheet, if you already have the rows

This is optional. Typing in the conversation is enough.

1. In the sidebar, under **Resources**, download **Incidents template** or **Situation logs template**.
2. Fill that file in.
3. On the message box, press **+**, then **Upload incidents CSV** or **Upload situation logs CSV**.

Check the Facts list after the upload, then follow the same steps: confirm the event, read Final, and press Issue.
